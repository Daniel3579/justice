# ОПИСАНИЕ ВАРИАНТОВ ИСПОЛЬЗОВАНИЯ СИСТЕМЫ «Генеративная система формирования исковых заявлений»

## 1 Общие сведения

Настоящий документ содержит описание вариантов использования автоматизированной системы «Генеративная система формирования исковых заявлений» (JUSTICE). Варианты использования отражают взаимодействие пользователя с системой и обработку основных и альтернативных сценариев в рамках текущей версии.

## 2 Участники и внешние системы

| Участник / система | Назначение |
| --- | --- |
| Пользователь | Вводит описание ситуации, уточняет сведения, задает вопросы, просматривает и экспортирует результат, управляет аккаунтом. |
| Администратор | Пользователь с is_admin=true; управляет корпусом и просматривает статистику. |
| Frontend JUSTICE | Предоставляет веб-интерфейс чата, страниц входа, профиля и панели администратора, отображает результаты и выполняет клиентские операции. |
| Backend JUSTICE | Принимает HTTP-запросы, управляет авторизацией и чатами, запускает генерацию, обработку диалога и экспорт, административные операции. |
| Ollama / LLM | Используется для извлечения фактов, классификации намерения, составления частей иска и ответов на вопросы. |
| ChromaDB | Предоставляет локальный поиск по подготовленной базе правовых документов. |
| DDGS | Обеспечивает веб-поиск правовой информации. |
| PostgreSQL | Хранит пользователей, сессии и историю чатов в серверном режиме, токены сброса и события. |
| SMTP | Отправка ссылок сброса пароля. |

## 3 Общие правила выполнения сценариев

- Основной интерфейс — чат; полный сценарий требует серверной авторизации (`VITE_MOCK_AUTH=false`).
- `/chat` и `/generate` принимают непустой текст до 8000 символов после удаления внешних пробелов.
- `/chat` использует LLM для классификации `new_case`, `update`, `question`, `off_topic`. `/generate` запускает генерацию напрямую.
- Защищены профиль, чаты, генерация, диалог и серверный экспорт; административные операции требуют роли администратора.
- Результат — проект иска, а не гарантированно юридически корректный документ. Недостающие сведения выводятся после генерации.
- Веб-поиск и локальный поиск при генерации выполняются параллельно; при вопросе используется только локальный поиск.

## 5 Ограничения и допущения

- `events` — счётчики операций, без FK пользователя и без содержания запроса. Запись выполняется в режиме best effort; ошибка записи журналируется и не отменяет основной результат.

- Mock-авторизация предназначена только для разработки и несовместима с полноценными защищенными запросами.
- Классификация LLM не гарантирует отказ от всех запросов вне потребительской тематики; прямой API генерации ее обходит.
- Известны дефекты ссылки восстановления, APP_URL и разной минимальной длины пароля.
- Нет TTL обычных сессий, гарантированного сохранения при сбоях клиента и атомарной переиндексации.
