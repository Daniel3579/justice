# 1 Общие сведения

## 1.1 Полное наименование системы

Полное наименование автоматизированной системы (АС): «Генеративная система формирования исковых заявлений». Сокращённое наименование — JUSTICE. Вид разработки — веб-ориентированный программный прототип подготовки проектов исковых заявлений по спорам о защите прав потребителей на русском языке с использованием больших языковых моделей и поиска правовой информации.

## 1.2 Основания для создания автоматизированной системы

Основанием является учебный командный проект группы ЭФМО-01-25. Настоящая редакция актуализирует ТЗ от 14.11.2026 с учётом предыдущих версий. Документ структурирован с учётом ГОСТ 34.602-2020 «Информационные технологии. Комплекс стандартов на автоматизированные системы. Техническое задание на создание автоматизированной системы».

# 2 Цели и назначение создания АС

## 2.1 Цели создания АС

Цель — сократить трудоёмкость подготовки первичного проекта искового заявления по потребительскому спору за счёт преобразования свободного описания в структурированные факты, поиска правовых материалов, расчёта предусмотренных денежных требований и составления документа. Пользователь должен получать проект без ручного заполнения всех юридических реквизитов, иметь возможность уточнить сведения, задать вопрос и сохранить результат. Администратор должен иметь средства сопровождения корпуса и просмотра агрегированной статистики.

| **Цель**                 | **Показатель достижения**                | **Способ проверки**                                                                                  |
|--------------------------|------------------------------------------|------------------------------------------------------------------------------------------------------|
| Автоматизация подготовки | Проект иска из свободной фабулы          | Сквозной сценарий формирования проекта; сравнение времени с ручной подготовкой — при наличии эталона |
| Извлечение фактов        | Корректные поля и отсутствующие сведения | Эталонная разметка CaseFacts                                                                         |
| Правовое обоснование     | Релевантные и актуальные нормы           | Оценка ссылок                                                                                        |
| Диалог                   | Четыре класса намерений                  | UC-03, 05, 06, 20                                                                                    |
| Экспорт                  | DOCX, PDF, MD, TXT, копирование          | Проверка файлов и содержимого                                                                        |
| Хранение и доступ        | Сохранность и изоляция чатов             | API и интеграционные тесты                                                                           |
| Администрирование        | Статистика и управляемый корпус          | UC-21–24                                                                                             |

Численные показатели экономии времени, качества LLM и допустимой нагрузки не установлены. Их измерение возможно в ходе испытаний без заранее заявленных порогов.

## 2.2 Назначение АС

АС предназначена для вспомогательной подготовки черновиков исковых заявлений по спорам о защите прав потребителей. Результат требует проверки реквизитов, фактов, применимости законодательства, расчётов и подсудности перед использованием. Система не подаёт иск в суд, не представляет пользователя и не гарантирует исход разбирательства.

## 2.3 Границы текущего MVP

Целевая версия включает чат и API, извлечение фактов, четыре класса намерений, локальный и веб-поиск, шаблонное формирование, расчёты, уточнение и вопросы, недостающие сведения, источники, экспорт DOCX/PDF/MD/TXT, копирование, серверные регистрацию и вход, историю, профиль, восстановление пароля, удаление аккаунта, темы и адаптивность, административную статистику, управление нормативными PDF и переиндексацию. Используются PostgreSQL и ChromaDB. Восстановление пароля и другие частично реализованные возможности требуют проверок и устранения ограничений, перечисленных в разделе 4.6. Перспективные функции (4.2.16) не входят в обязательную приёмку текущего MVP.

# 3 Характеристика объекта автоматизации

Автоматизируется подготовка проекта искового заявления: ввод фабулы, систематизация фактов, поиск информационной основы, построение текста и требований, расчёт, уточнение, сохранение и получение документа.

## 3.1 Условия эксплуатации

Для полноценной работы требуются браузер, FastAPI, доступный PostgreSQL и Ollama. Поиск зависит от корпуса ChromaDB и доступности DDGS. При отказе отдельного поискового сервиса должна сохраняться возможность работы с доступным источником. В контейнерном режиме веб-интерфейс доступен на порту 8082, backend API — на порту 8000, Adminer — на порту 8081. PostgreSQL доступен на порту 5433 хостовой системы и использует порт 5432 внутри контейнерной сети.

# 4 Требования к автоматизированной системе

## 4.1 Требования к структуре АС

Система должна иметь модульную клиент-серверную архитектуру. Клиент отвечает за представление и взаимодействие, сервер — за проверку доступа и данных, бизнес-логику, поиск, вызов LLM, расчёт, хранение и экспорт. Реляционные пользовательские данные отделяются от правового корпуса и векторного индекса. Frontend не должен обращаться непосредственно к БД, Ollama, ChromaDB или SMTP.

| **Компонент**   | **Реализация**                                                 | **Назначение**                                      |
|-----------------|----------------------------------------------------------------|-----------------------------------------------------|
| Frontend        | React 19, TypeScript, Vite, React Router, CSS                  | Чат, профиль, восстановление, история, админ-панель |
| API-клиент      | api/client.ts, auth.ts, generate.ts, chats.ts, admin.ts        | HTTP, Bearer, ошибки                                |
| API             | FastAPI, Pydantic, Uvicorn; main.py                            | Маршруты и валидация                                |
| Хранение        | PostgreSQL 16, psycopg; storage.py                             | Пользователи, сессии, чаты, сбросы, события         |
| Оркестрация     | generator.py, prompts.py, schemas.py                           | Классификация, извлечение, составление              |
| LLM             | Ollama, Qwen 3.5 4B; llm.py                                    | Структурированные и текстовые ответы                |
| Локальный поиск | db.py, retriever.py, embeddings.py; ChromaDB, nomic-embed-text | Поиск и индексация                                  |
| Веб-поиск       | web_search.py, DDGS                                            | Дополнительные материалы                            |
| Расчёт          | calc.py                                                        | Детерминированные денежные расчёты                  |
| Документы       | render.py, isk.j2; Jinja2, python-docx, ReportLab              | Шаблон, экспорт                                     |
| Почта           | mailer.py, SMTP                                                | Ссылка сброса                                       |
| Индекс          | indexer.py                                                     | Фоновая переиндексация                              |

Компоненты взаимодействуют через HTTP/JSON, внутренние вызовы Python и хранилища. Архитектурная схема приведена в приложении А. Подробные схемы и потоки ведутся в Architecture.md.

## 4.2 Функциональные требования

### 4.2.1 Ввод и отправка описания

| **ID** | **Требование**                                                                                                       |
|--------|----------------------------------------------------------------------------------------------------------------------|
| FR-001 | Предоставлять поле чата; Enter отправляет, Shift+Enter добавляет перенос строки.                                     |
| FR-002 | После удаления крайних пробелов принимать текст длиной 1–8000 символов; пустой и более длинный отклонять с HTTP 400. |
| FR-003 | Показывать ожидание обработки                                                                                        |

### 4.2.2 Извлечение фактов

| **ID** | **Требование**                                                                                   |
|--------|--------------------------------------------------------------------------------------------------|
| FR-006 | Извлекать юридически значимые факты в CaseFacts.                                                 |
| FR-007 | Нормализовать строки, суммы, даты, логические признаки, списки и объекты сторон.                 |
| FR-008 | Не подменять отсутствующие сведения вымышленными фактами; проверять это на контрольных примерах. |
| FR-009 | Определять тип нарушения из delay_goods, delay_service, defect, refund_refusal, other.           |

Поддерживаемые форматы дат: ДД.ММ.ГГГГ, ГГГГ-ММ-ДД, ДД.ММ.ГГ, ДД/ММ/ГГГГ. Денежные суммы могут поступать как числа или строки с пробелами, запятой и сокращением «тыс.». Нераспознанные значения не должны приниматься за достоверные факты.

### 4.2.3 Поиск правовой информации

| **ID** | **Требование**                                                                                 |
|--------|------------------------------------------------------------------------------------------------|
| FR-010 | Формировать локальный запрос по предмету и описанию нарушения, веб-запрос — по теме нарушения. |
| FR-011 | Параллельно искать локальные и веб-материалы при генерации.                                    |
| FR-012 | Получать до трёх локальных и трёх веб-результатов по умолчанию; маркировать НОРМА-n и WEB-n.   |
| FR-013 | Возвращать название, URL при наличии, выдержку и признак использования.                        |

## 4.4 Требования к данным и векторной базе

### 4.4.1 Структурированные данные дела

CaseFacts — промежуточный объект конвейера, не отдельная таблица PostgreSQL. Полная карточка дела сохраняется в JSONB истории чата. Наличие пустого поля допустимо для черновика, но отсутствующие значимые реквизиты должны обозначаться, а не заменяться выдуманными.

|-----------------------------------------------------|------------------|----------------------------------------------------|
| plaintiff                                           | Объект Plaintiff | ФИО и доступные реквизиты истца                    |
| defendant                                           | Объект Defendant | Наименование, адрес, ИНН, ОГРН                     |
| court                                               | string/null      | Суд                                                |
| contract_type, contract_number                      | string/null      | Вид и номер договора                               |
| contract_date, paid_date, deadline_date, claim_date | date/null        | Даты договора, оплаты, срока исполнения, претензии |
| subject                                             | string/null      | Товар, работа, услуга                              |
| price, paid_amount, moral_damage                    | number/null      | Цена, оплата и моральный вред                      |
| violation_type                                      | enum             | Поддерживаемый тип нарушения                       |
| violation_description                               | string/null      | Обстоятельства нарушения                           |
| claim_sent                                          | boolean/null     | Признак претензии                                  |
| claim_response                                      | string/null      | Ответ на претензию                                 |
| extra_demands, documents                            | array\[string\]  | Требования и текстовый перечень документов         |

### 4.4.2 Реляционное хранилище

Целевое хранилище — PostgreSQL. Инициализация производится storage.init_db. Полная SQL-схема — приложение Г. Backend должен определять email владельца по сессии, а не по произвольному значению клиента.

### 4.4.3 Правовой корпус и ChromaDB

Исходный правовой корпус размещается в каталоге data/documents и включает нормативные правовые материалы и примеры исковых заявлений по спорам о защите прав потребителей. В состав исходного корпуса входят материалы ГПК РФ (главы 12 и 14), Закон РФ «О защите прав потребителей» и восемь примеров исковых заявлений. Для локального семантического поиска используется ChromaDB. После изменения состава корпуса необходимо выполнять переиндексацию.

# 8 Подготовка к вводу в действие

## 8.1 Окружение

Для контейнерного режима необходимо подготовить Docker и Docker Compose, обеспечить наличие достаточных вычислительных ресурсов и доступность Ollama. Установить модели qwen3.5:4b и nomic-embed-text с помощью команды ollama pull. При использовании отдельно запущенной Ollama выполнить docker compose up -d --build; при контейнерном размещении Ollama использовать дополнительный файл docker-compose.ollama.yml согласно инструкции проекта.

При развёртывании используется поставляемый вместе с проектом правовой корпус, размещённый в каталоге data/documents и включающий 10 PDF-документов. Необходимо проверить доступность документов и работоспособность векторного индекса ChromaDB. При отсутствии индекса выполняется его построение, при некорректном состоянии или изменении состава корпуса — переиндексация. Для экспорта исковых заявлений в PDF необходимо обеспечить наличие шрифтов с поддержкой кириллицы.

Для локального запуска необходимо подготовить PostgreSQL и Python, установить зависимости из app/requirements.txt, настроить параметры подключения к базе данных и Ollama, запустить python start.py из каталога app. Установить Node.js и npm, в каталоге frontend выполнить npm install и npm run dev, предварительно установив параметр VITE_MOCK_AUTH=false.

Перед запуском необходимо настроить переменные окружения, включая ADMIN_EMAILS, APP_URL и параметры SMTP для восстановления пароля.

Веб-интерфейс доступен при локальном запуске по адресу http://localhost:5173, при контейнерном — http://localhost:8082. Документация OpenAPI доступна по адресу http://127.0.0.1:8000/docs. В контейнерном режиме PostgreSQL использует порт 5432 внутри контейнерной сети и порт 5433 для подключения с хостовой системы. Интерфейс Adminer доступен по адресу <http://localhost:8081>.

Защищённые запросы используют Authorization: Bearer \<access_token\>. JSON — application/json. Загрузка — multipart/form-data, поле files. POST /export/{fmt} возвращает Content-Disposition с именем iskovoe_zayavlenie и расширением, DOCX/PDF/Markdown MIME. Ошибки: см. 4.2.8. Схема history для /chat: элементы role=user/assistant и content; case — ранее сформированная карточка. PUT /chats/{chat_id} принимает title (до 200 символов) и messages — массив объектов.
